1. Why We Need to Understand Addressing

Every device on a network needs a unique address so traffic knows where to go. Two addressing schemes matter today:

  • IPv4 - the original scheme, 32-bit addresses, running out of room.
  • IPv6 - the replacement, 128-bit addresses, built for a much bigger internet.

Understanding both, and the CIDR notation used to describe network sizes, is foundational for anyone working with servers, routers, or cloud infrastructure.

2. IPv4 Recap

An IPv4 address is 32 bits, written as four decimal numbers from 0 to 255 separated by dots:

192.168.1.10

Each address is split into two conceptual parts: the network portion, which identifies which network the device is on, and the host portion, which identifies the specific device on that network.

The question is: how many bits belong to each part? That is what CIDR notation answers.

What is an octet?

An octet is a group of 8 bits. Each IPv4 address is 32 bits total, split into four octets separated by dots. Each octet ranges from 0 to 255 because 28 gives 256 possible values.

Detail: Converting an octet

Binary:  11000000
Decimal: 128+64 = 192

So 11000000.10101000.00000001.00001010 in binary becomes 192.168.1.10 in dotted-decimal. IPv6 does not use octets in the same written form; it groups bits into 16-bit hextets, with 4 hex digits each.

3. CIDR Notation - What the /xx Means

CIDR means Classless Inter-Domain Routing. The number after the slash tells you how many bits, counting from the left, are the network portion.

192.168.1.0/24
             ^
    first 24 bits = network
    remaining 8 bits = host

Click a box above for a detailed breakdown

Detail: The network portion

The first N bits are shared by every device on the same subnet. This is the part a router uses to decide which direction to forward a packet without needing to know the exact device.

  1. Total bits in IPv4 = 32.
  2. Network bits = the CIDR number, such as 24.
  3. Host bits = 32 minus network bits, such as 32 - 24 = 8.

Back to CIDR notation

Detail: The host portion

The remaining bits identify the individual device within that network. The number of host bits determines how many addresses exist in the block.

  • Number of addresses = 2host bits.
  • Usable hosts = addresses minus 2, because the network address and broadcast address are reserved.

Worked example: 192.168.1.0/26

StepValue
Network bits26
Host bits32 - 26 = 6
Total addresses2^6 = 64
Usable hosts64 - 2 = 62
Network address192.168.1.0
Broadcast address192.168.1.63
Usable range192.168.1.1 to 192.168.1.62

Back to CIDR notation

Practice problems with answers

  1. 10.0.0.0/28 - how many usable hosts?
    Host bits = 32 - 28 = 4, so 2^4 = 16 addresses and 14 usable hosts.
  2. 172.16.5.0/23 - what is the broadcast address?
    A /23 spans two /24 blocks, from 172.16.4.0 to 172.16.5.255, so the broadcast address is 172.16.5.255.
  3. You need a subnet for 100 devices. What is the smallest CIDR block that fits?
    /25 gives 126 usable hosts, which fits 100. /25 is the answer; /26 only gives 62, which is too small.

3a. A Simple IPv4 Network in Practice

Here is how CIDR and addressing come together in a typical home or office network: a router sits between the public internet and a private LAN.

Click a box above for a detailed explanation

Detail: The public internet side

Only the router's public IP is ever visible to the outside world. From the internet's perspective, every device behind the router - laptop, phone, printer - is completely invisible; the only address anyone out there ever sees is that one public IP.

Back to the network diagram

Detail: What the router does with NAT

The router has two addresses: a public IP such as 41.13.x.x facing the internet, and a private IP such as 192.168.1.1 on the LAN side. NAT, or Network Address Translation, is what lets many private devices share that one public IP:

  1. A device sends a packet with source 192.168.1.10 and destination some-website.com.
  2. The router rewrites the source address to its own public IP, such as 41.13.x.x, and picks a unique port to track the connection.
  3. It records the mapping from that port back to 192.168.1.10 in a NAT table.
  4. The website replies to 41.13.x.x on that port.
  5. The router looks up the NAT table and rewrites the destination back to 192.168.1.10 before forwarding it onto the LAN.

This is also why IPv6 mostly eliminates the need for NAT: with enough address space for every device to have its own globally routable address, there is no need to share and translate a single public IP.

Back to the network diagram

Detail: How devices get their address

Devices on the LAN, such as 192.168.1.0/24, get private addresses automatically via DHCP, or Dynamic Host Configuration Protocol. The router hands out an available address from its pool, along with the subnet mask, default gateway, and DNS server to use.

Back to the network diagram

4. IPv6 Basics

IPv6 exists because IPv4's roughly 4.3 billion addresses are not enough for a world of billions of connected devices. IPv6 uses 128-bit addresses, an address space so large, 2128, that exhaustion is not a realistic concern.

Address format

2001:0db8:85a3:0000:0000:8a2e:0370:7334

IPv6 addresses are written as 8 groups of 4 hexadecimal digits separated by colons. Each group represents 16 bits, giving 8 x 16 = 128 bits total.

Click either address for the shortening rules

Detail: Shortening rules

  1. Drop leading zeros in each group: 0db8 becomes db8.
  2. Collapse one run of consecutive all-zero groups to ::. This can only happen once per address.

CIDR still applies

IPv6 uses the same CIDR slash notation, just with 128 bits instead of 32. For example, 2001:db8::/32 means the first 32 bits are the network portion, leaving 96 bits for subnetting and hosts.

Convention worth teaching: ISPs typically hand out a /64 to a single subnet, such as a LAN, and often a /48 or /56 to a customer site covering multiple subnets.

Back to IPv6 basics

6. IP Addressing vs Hardware (MAC) Addressing

IP and MAC addresses operate at different layers and serve different purposes.

IP AddressMAC Address
LayerNetwork layer, Layer 3Data Link layer, Layer 2
Assigned bySoftware or network admin, either static or DHCPBurned into the NIC by the manufacturer
ScopeLogical and can changePhysical and usually fixed, though spoofable
Format192.168.1.10 or 2001:db8::100:1A:2B:3C:4D:5E, 48-bit hex
PurposeRouting traffic between networksDelivering frames within a local segment

How they relate: ARP / NDP

When a device sends data to another device on the same local network, it needs that device's MAC address, not just its IP address. This is resolved by ARP in IPv4, which broadcasts "who has this IP?", and NDP in IPv6, which uses multicast.

Encapsulation

Every packet sent locally is wrapped in a frame with source and destination MAC addresses, while carrying source and destination IP addresses inside it.

Click the frame or the packet for details

Detail: The MAC header

The MAC header is rewritten at every router hop. A router strips the incoming frame's MAC header and builds a new one addressed to the next segment's device, because a destination MAC only has meaning within that next local segment.

Nuance: MAC addressing scope extends across an entire broadcast domain, which can span many switches or even tunneled links via VXLAN, MPLS, or bridged VPNs. The actual boundary where MAC scope ends is a router, a Layer 3 boundary, not physical distance.

Back to IP vs MAC

Detail: The IP header

The IP header stays constant for the whole journey, hop to hop, until it reaches the final destination. This is what makes end-to-end routing possible: every router along the way reads the destination IP to decide the next hop without needing to rewrite it.

Why not just use the hardware address for everything?

  1. Not hierarchical: an IP address has structure. The network portion narrows location, like a postal code. A MAC address is a flat, manufacturer-assigned serial number with no way to infer location.
  2. Does not reflect movement: a MAC stays the same wherever a device goes, but IP addressing lets a device get a new, location-appropriate address via DHCP when it moves networks.
  3. Would require every router on earth to know every device individually: with no way to summarize or aggregate, unlike hierarchical IP routing.

7. How Cellular Networks Work

Cellular networks are different from wired networking, but they connect back to IP addressing once traffic reaches the carrier's core.

Click a stage above for a detailed explanation

Detail: Radio Access Network

Coverage area is divided into cells, each served by one base station, or cell tower. Neighboring cells use different radio frequencies to avoid interference, but cells far enough apart reuse the same frequencies. This is how the system scales to millions of users without needing infinite spectrum.

As a phone moves between cells, it performs a handover, re-associating with the new tower without dropping the connection. The phone talks to the nearest base station, eNodeB in 4G/LTE or gNodeB in 5G, over radio, handling signal modulation, error correction, and sharing frequency bands across many phones at once.

Back to cellular networks

Detail: Core network

The carrier core is the carrier's brain behind the towers, handling:

  • Authentication: verifying the SIM is legitimate.
  • Mobility management: tracking which cell a device is in so traffic can be routed to it.
  • Routing to the internet or phone system: traffic gets NAT'd and routed out to the public internet. Voice is either routed through the traditional phone system on older networks or carried as IP traffic with VoLTE.

Back to cellular networks

Detail: Where IP addressing fits in

Once data leaves the RAN and enters the core network, it becomes ordinary IP traffic. The phone gets assigned an IP address, often via carrier-side DHCP, typically behind carrier-grade NAT because carriers do not have enough public IPv4 addresses for every subscriber. This NAT pressure is one of the biggest real-world drivers of IPv6 adoption; mobile carriers were among the first to deploy it at scale.

Generational summary

8. Suggested Exercises for Students

  1. Convert a full IPv6 address to its shortened form and back again.
  2. Given an IPv4 network and a required host count, calculate the correct CIDR block.
  3. Identify the address type from a list of sample IPv6 addresses.
  4. Subnet a /24 IPv4 network into four equal /26 subnets and list each subnet's network address, broadcast address, and usable range.
  5. Explain why mobile carriers were early adopters of IPv6, connecting it back to carrier-grade NAT and address exhaustion.
  6. Trace what happens to the MAC and IP headers of a packet as it crosses two routers on its way to a destination. What changes at each hop, and what stays the same?
