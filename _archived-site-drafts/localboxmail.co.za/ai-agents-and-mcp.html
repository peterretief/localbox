AI Agents and MCP

Understand how agents choose tools, how MCP connects them to real systems, and how to build safe examples around Raspberry Pi and email services.

1. Model, assistant and agent

A language model predicts and generates text. An assistant combines a model with instructions and conversation context. An agent adds the ability to decide when to use tools, observe results and continue working toward a goal.

SystemMain capability
ModelGenerate or classify content from input
AssistantApply instructions in a conversation
AgentSelect actions, call tools and use results

2. Clickable agent loop

The loop stops when the goal is complete, the agent needs the user, or a safety or resource limit is reached.

3. Tools

A tool is a named operation with a clear input schema and a predictable result. Good agent tools are narrower than shell access.

{
  "name": "get_disk_usage",
  "description": "Return filesystem usage for the Raspberry Pi",
  "input": {"path": "/"}
}

Read-only

Get temperature, read logs, list services or query DNS.

Changing state

Restart a service, write a file or update configuration.

Destructive

Delete data, revoke access or wipe storage. These need strong safeguards.

Back to agent loop

4. MCP architecture

Model Context Protocol gives an AI application a standard way to discover and use tools, resources and reusable prompts exposed by an MCP server.

The MCP server is an adapter around real systems. It might read files, call a Go service, query a database or inspect a Raspberry Pi. The agent does not need a different integration design for every application.

Back to agent loop

5. Example: Raspberry Pi health agent

User: Why is the Raspberry Pi slow?

Agent calls:
1. get_load_average
2. get_cpu_temperature
3. get_memory_usage
4. get_disk_usage
5. list_busy_processes

Agent response:
Disk usage is 98% on /. The largest directory is /var/log.
CPU temperature and memory are normal.

Each result should include units, timestamps and errors. The agent should not delete logs automatically; it should explain the finding and offer a controlled cleanup action.

6. Example: email troubleshooting agent

User: Why was mail to user@example.net rejected?

Agent calls:
1. find_mail_log(message_id)
2. parse_smtp_reply(log_entry)
3. lookup_mx("example.net")
4. check_spf("sender.example")
5. check_dmarc("sender.example")

The answer should quote the decisive SMTP status, identify which server issued it and distinguish evidence from a suggested cause.

7. Safety and approval

Read-only observation can usually be automatic. State-changing actions should be explicit, narrow and auditable.

ActionDefault policy
Read CPU temperatureAllow
Read recent service logsAllow with log-size limits
Restart NginxAsk for approval
Edit firewall rulesRequire approval and validation
Delete mail queueDo not expose as a broad tool

8. Small Go-backed tool example

A safe first tool can expose disk usage as JSON through a local HTTP service. An MCP server can then wrap that endpoint.

package main

import (
    "encoding/json"
    "net/http"
    "syscall"
)

type DiskUsage struct {
    Total uint64 `json:"total_bytes"`
    Free  uint64 `json:"free_bytes"`
}

func disk(w http.ResponseWriter, r *http.Request) {
    var s syscall.Statfs_t
    if err := syscall.Statfs("/", &s); err != nil {
        http.Error(w, err.Error(), http.StatusInternalServerError)
        return
    }
    json.NewEncoder(w).Encode(DiskUsage{
        Total: s.Blocks * uint64(s.Bsize),
        Free:  s.Bavail * uint64(s.Bsize),
    })
}

func main() {
    http.HandleFunc("/tools/disk-usage", disk)
    http.ListenAndServe("127.0.0.1:8081", nil)
}

Binding to loopback keeps the service local. Add authentication, timeouts, structured errors and tests before exposing it more widely.

9. Suggested exercises

  1. Classify ten possible tools as read-only, state-changing or destructive.
  2. Design the JSON schema for get_service_status.
  3. Draw the path from an agent through MCP to a Go service on a Raspberry Pi.
  4. Add a user-approval step before restart_service.
  5. Build a mock email tool that returns a fixed SMTP rejection and make the agent explain it.
