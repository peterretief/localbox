1. Why use a mesh VPN?

A conventional VPN often sends every connection through one central gateway. A mesh VPN gives approved devices private identities and allows encrypted device-to-device communication where possible. This is useful when LocalBox systems are spread across homes, offices, cloud servers and mobile networks.

Reach private services

Connect to SSH, web dashboards, databases and files without publishing them directly on the public internet.

Work through NAT

Devices can often connect through home routers, mobile networks and restrictive firewalls without port forwarding.

Stable identity

A device keeps a private mesh identity even when its ordinary Wi-Fi or mobile address changes.

LocalBox idea: a Raspberry Pi can remain inside a private network while an authorised laptop or phone reaches it through the mesh.

2. Tailscale and Headscale

ComponentPurposeOperator
Tailscale clientRuns on each device, creates the encrypted interface and exchanges traffic.You install it on Linux, Windows, macOS, Android, iOS and supported servers.
Tailscale control serviceAuthenticates users and devices, distributes network information and applies policy.Tailscale operates the hosted service.
HeadscaleSelf-hosted open-source implementation of the Tailscale control server.You operate its HTTPS, upgrades, backups, identity and policy.

Headscale does not replace the Tailscale client. Devices still run the client but use your Headscale URL as their control server.

Tradeoff: self-hosting gives more control but also gives you more operational responsibility.

4. Control plane and data plane

Control plane

Handles identity, device registration, addresses, keys, routes, policy and peer discovery.

Data plane

Carries encrypted SSH, HTTP, database and other IP traffic between approved devices.

The control server helps peers discover and trust one another, but is not normally intended to inspect the contents of their encrypted application traffic.

5. Install the Tailscale client

On a supported Linux system, install the client and inspect the service:

curl -fsSL https://tailscale.com/install.sh | sh
tailscale version
sudo systemctl status tailscaled
sudo tailscale status

On Alpine Linux, service management uses OpenRC:

apk add tailscale
rc-update add tailscale default
rc-service tailscale start
Verify first: package availability and service setup can vary by distribution and version.

6. Join a Tailscale or Headscale network

For hosted Tailscale:

sudo tailscale up
tailscale status
tailscale ip -4
tailscale ping other-device-name

For Headscale, specify the alternate control server and use a short-lived key:

sudo tailscale up --login-server=https://headscale.example.com --auth-key=REDACTED
tailscale status
tailscale netcheck

Treat authentication keys like passwords. Do not publish them in screenshots, shell history, repositories or course pages.

7. Prepare a Headscale server

Headscale should run on a publicly reachable server with a proper HTTPS name such as headscale.example.com. Plan the public DNS name, TLS, dedicated service account, configuration, database, backups and logs.

sudo nano /etc/headscale/config.yaml
sudo systemctl restart headscale
sudo systemctl status headscale
sudo journalctl -u headscale -n 100 --no-pager
sudo headscale help
sudo headscale users --help
sudo headscale preauthkeys --help
sudo headscale nodes --help

Headscale CLI syntax evolves. Use help on the installed release before automating user, key, node or route commands.

8. Private names and MagicDNS

Private DNS lets learners use names instead of mesh IP addresses. Configure it deliberately and inspect split-DNS domains if enabling mesh DNS affects ordinary internet lookups.

getent hosts localmail
resolvectl status
cat /etc/resolv.conf
tailscale status

A name such as localmail can point to a private mesh address while remaining unavailable to the public internet.

9. Subnet routers

A subnet router allows mesh devices to reach systems that do not run Tailscale. A Raspberry Pi can advertise a laboratory or clinic LAN.

sudo sysctl -w net.ipv4.ip_forward=1
sudo tailscale up --advertise-routes=10.0.0.0/24

The route must also be approved in the control plane. Avoid overlapping ranges such as using 192.168.1.0/24 on both sides of the connection.

10. Exit nodes

An exit node routes a client's ordinary internet traffic through another mesh device. This can be useful on untrusted Wi-Fi, but it is broader than exposing one private subnet.

sudo tailscale up --advertise-exit-node
sudo tailscale up --exit-node=exit-node-name
sudo tailscale up --exit-node=
Grant carefully: approve exit-node use only where it is intentional and understood.

11. Access control

A private address does not mean every device should reach every service. Apply least privilege and allow only the users, devices and ports needed.

Administrators → SSH to servers
Students       → HTTP/HTTPS training services
Mail operators → IMAP/SMTP administration
Sensors        → one ingest service
Guests         → no server administration

Test policy changes from a second session so you do not lock yourself out.

12. Raspberry Pi LocalBox example

Join a Raspberry Pi and laptop to the same Headscale-controlled mesh, then access a private service without publishing it on the internet.

# On the Pi
sudo tailscale up --login-server=https://headscale.example.com --auth-key=REDACTED
hostname
tailscale status
tailscale ip -4
ss -tulpn

# On the laptop
sudo tailscale up --login-server=https://headscale.example.com --auth-key=REDACTED
tailscale ping raspberry-pi-name
ssh peter@raspberry-pi-name
curl http://raspberry-pi-name

If the Pi hosts a service on port 8080, the laptop can reach it over the private mesh without publishing port 8080 on the home router.

13. Troubleshooting

QuestionCheck
Is the daemon running?systemctl status tailscaled or rc-service tailscale status
Did the node join?tailscale status and Headscale node list
Does the peer answer?tailscale ping peer
Is the service listening?ss -tulpn
Does private DNS resolve?getent hosts NAME
Can UDP work?tailscale netcheck
What changed?Client and Headscale logs

If enabling Tailscale breaks internet access, disconnect any exit node, inspect DNS and routes, check for overlapping subnets, run tailscale netcheck, and temporarily use sudo tailscale down to confirm the cause.

14. Security checklist

  • Serve Headscale over valid HTTPS.
  • Keep Headscale and clients updated.
  • Use short-lived, non-reusable authentication keys where practical.
  • Remove old devices promptly.
  • Back up Headscale configuration and database securely.
  • Apply least-privilege policy.
  • Require approval for subnet routes and exit nodes.
  • Protect SSH keys and administration endpoints.
  • Keep an out-of-band recovery path to the Headscale server.

15. Suggested exercises

  1. Install Tailscale on two machines and record their mesh IP addresses.
  2. Compare tailscale ping with ordinary ping.
  3. Run an HTTP service on a Pi and access it only through the mesh.
  4. Configure private DNS and test it with getent hosts.
  5. Explain the difference between a subnet router and an exit node.
  6. Advertise a laboratory subnet and verify route approval.
  7. Diagnose a private DNS failure without changing unrelated settings.
  8. Write a least-privilege plan for an administrator, student and sensor node.
