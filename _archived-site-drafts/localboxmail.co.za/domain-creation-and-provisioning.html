1. What does “creating a domain” mean?

A domain name is not manufactured on a server. It is registered through a registrar and connected to services through DNS. Provisioning is the work that follows: preparing the DNS records, server, website, security certificate and optional email service.

Registration

Reserves the name for a period and records responsibility.

DNS

Publishes instructions telling clients where services live.

Provisioning

Creates and configures the infrastructure answering for the name.

Mental model: the domain is the human-readable address, DNS is the directory, and the provisioned server is the building providing the service.

3. Choose and check the domain name

A useful name should be easy to spell, say aloud and connect to the service. Check availability and avoid confusion with an existing brand.

  • Keep the name short and easy to type.
  • Choose a relevant suffix such as .co.za, .org.za or .com.
  • Plan subdomains such as www, mail, learn, api and status.
dig example.co.za
whois example.co.za

A missing DNS answer does not prove availability. The registrar check is the final authority.

4. Register the domain

The registrar submits registration to the registry responsible for the suffix. Select the period, provide contact information, pay the fee and choose nameservers.

RoleResponsibility
RegistrantPerson or organisation holding the right to use the domain.
RegistrarCompany through which it is registered and renewed.
RegistryOrganisation operating the suffix database.
DNS providerService hosting the authoritative zone.
Important: record renewal, secure the registrar account and keep the administrative email reachable.

5. Create the DNS zone

A zone is the managed collection of records telling clients where each service lives.

RecordPurposeExample
AIPv4 address@ → 203.0.113.10
AAAAIPv6 address@ → 2001:db8::10
CNAMEHostname aliaswww → example.co.za
MXMail receiving hosts10 mail.example.co.za
TXTVerification and policySPF, DKIM, DMARC
CAAAllowed certificate authorities0 issue letsencrypt.org
@ 300 IN A 203.0.113.10
www 300 IN CNAME example.co.za.
dig example.co.za A
dig example.co.za NS
dig +trace example.co.za
Propagation: caching and TTL values mean some clients may see an old answer until it expires.

6. Provision the server

Provisioning prepares the machine providing the service: a cloud VM, dedicated server, Raspberry Pi or machine reached through a secure tunnel.

Operating system

Install a supported Linux system and apply updates.

Access

Create an administrator and use SSH keys where practical.

Network

Open only required ports and confirm listening services.

apk update && apk upgrade
sudo apt update && sudo apt upgrade
ip addr
ip route
ss -tulpn

7. Deploy the website

Place files in a readable document root and configure a virtual host that recognises the requested hostname.

server_name example.co.za www.example.co.za;
root /var/www/example.co.za;
index index.html;
sudo mkdir -p /var/www/example.co.za
sudo nginx -t
sudo systemctl reload nginx

Test locally before changing public DNS:

curl -I http://127.0.0.1
curl -I -H 'Host: example.co.za' http://127.0.0.1
Good practice: test the web server locally before blaming DNS.

8. Enable HTTPS

HTTPS protects traffic and the certificate proves that the server is authorised to use the hostname.

Validation

The certificate authority checks control of the hostname.

Installation

The certificate and private key are configured on the server.

Renewal

Automate renewal before certificates expire.

sudo certbot --nginx -d example.co.za -d www.example.co.za
openssl s_client -connect example.co.za:443 -servername example.co.za

9. Provision email for the domain

Email provisioning is separate from website provisioning. Use a local mail server, a provider, or a combination.

RecordPurpose
MXNames the receiving mail server.
SPFPublishes allowed envelope senders.
DKIMPublishes a key verifying signed messages.
DMARCDefines alignment, policy and reporting.
@ IN MX 10 mail.example.co.za.
mail IN A 203.0.113.20
@ IN TXT "v=spf1 ip4:203.0.113.20 -all"
_dmarc IN TXT "v=DMARC1; p=none; rua=mailto:dmarc@example.co.za"
dig example.co.za MX
dig _dmarc.example.co.za TXT

Begin DMARC cautiously, inspect reports and enforce strictly only after legitimate senders are aligned.

10. Create subdomains for separate services

Subdomains divide a domain into clear service names and can point to different servers or providers.

NamePossible purpose
www.example.co.zaPublic website
learn.example.co.zaTraining platform
mail.example.co.zaMail server or webmail
api.example.co.zaApplication API
status.example.co.zaStatus page
www IN CNAME example.co.za.
learn IN A 203.0.113.10
api IN A 203.0.113.11
mail IN A 203.0.113.20

11. Automate repeatable provisioning

Manual provisioning is valuable for learning, but repeated deployments benefit from tested automation.

Templates

Standardise server blocks, directories and DNS records.

Scripts

Create files, permissions, validation and reloads.

Provider APIs

Create DNS and infrastructure programmatically where supported.

DOMAIN="$1"
WEBROOT="/var/www/$DOMAIN"
mkdir -p "$WEBROOT"
printf '<h1>%s is ready</h1>\n' "$DOMAIN" > "$WEBROOT/index.html"
nginx -t
rc-service nginx reload

Production automation should handle backups, logs, certificates, ownership, secrets, health checks and rollback.

Security: never put registrar passwords, DNS API tokens or private keys in public source code.

13. Domain deployment checklist

  1. Confirm spelling, register the domain and record renewal.
  2. Secure the registrar account and set nameservers.
  3. Create website A/AAAA and www records.
  4. Provision and update the server.
  5. Create a non-root administrator and secure SSH.
  6. Install the web server, upload the site and validate configuration.
  7. Test with the correct Host header and allow required ports.
  8. Issue the TLS certificate and confirm renewal.
  9. Create MX, SPF, DKIM and DMARC records if email is included.
  10. Test externally and document providers, DNS, backups, logs and health checks.

14. Suggested exercises

  1. Draw the path from entering a domain in a browser to receiving HTML.
  2. Create a test zone with an apex A record and www CNAME.
  3. Compare an authoritative DNS answer with your normal resolver.
  4. Create an Nginx virtual host and test it with a custom Host header.
  5. Explain why correct DNS can still lead to a 404 or wrong site.
  6. Design MX, SPF, DKIM and DMARC records for a test domain.
  7. Write a provisioning script that validates names and runs nginx -t.
  8. Create a rollback plan for a failed DNS or web-server change.
