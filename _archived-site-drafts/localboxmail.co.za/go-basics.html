A Beginner's Guide to Go

1. Why Go?

Go, also called Golang, was built at Google for building reliable, simple, fast software, especially networked services and command-line tools. It compiles to a single static binary, has built-in concurrency, and deliberately keeps the language small so there is less to learn and less to disagree about in code review.

You will feel at home quickly if you have used C, Python, or JavaScript. Go borrows C-like syntax with Python-like readability, minus the class hierarchies and minus manual memory management, because it has a garbage collector.

2. Program Structure

Every Go file belongs to a package, can import other packages, and an executable program needs exactly one func main() as its entry point.

package main

import "fmt"

func main() {
    fmt.Println("Hello, Go")
}

Click a section above for a detailed explanation

Detail: Packages

Every Go source file starts with a package declaration. Files in the same directory that share a package name form one compilation unit and can freely call each other's functions without imports.

package main is special: it tells the Go compiler this package produces an executable binary, not a reusable library. Any other package name, such as package provisioning, produces a library that other code can import.

Back to program structure

Detail: Imports

The import block pulls in other packages, including standard library ones like fmt and net/http, or third-party ones fetched with go get. Go is strict: importing a package you do not use is a compile error.

import (
    "fmt"
    "net/http"
    "github.com/some/package"
)

Back to program structure

Detail: func main()

Execution always starts at main() in package main. It takes no arguments and returns nothing. Command-line args come from os.Args, and the exit code comes from os.Exit() if you need a non-zero one.

fmt.Println is the most common way to print output while learning. It is part of the standard library's fmt package, no install required.

Back to program structure

3. Variables & Types

Go is statically typed. Every variable has a fixed type, checked at compile time. You can declare explicitly or let Go infer the type:

var name string = "Peter"   // explicit
var age = 34                // inferred as int
count := 0                  // shorthand, inferred (only inside functions)

Common built-in types

CategoryTypes
Integersint, int8, int16, int32, int64, uint...
Floating pointfloat32, float64
Textstring, rune for a single Unicode code point, byte
Booleanbool, true or false
Collectionsarray, slice, map

Zero values: unlike some languages, an uninitialized Go variable is never garbage. It gets a sensible default: 0 for numbers, "" for strings, false for booleans, and nil for pointers, slices, and maps.

4. Control Flow

Go keeps control flow minimal. There is no while, no ternary operator, and parentheses around conditions are omitted by convention.

if age >= 18 {
    fmt.Println("adult")
} else {
    fmt.Println("minor")
}

for i := 0; i < 5; i++ {
    fmt.Println(i)
}

switch day {
case "Sat", "Sun":
    fmt.Println("weekend")
default:
    fmt.Println("weekday")
}

Note for beginners: Go's for is the only loop construct. It doubles as a while loop when you drop the init/post clauses, as in for count < 10 { ... }, and as an infinite loop with just for { ... }.

5. Functions

Go functions can return multiple values. This is used everywhere, especially for the idiomatic (result, error) pattern.

func divide(a, b int) (int, error) {
    if b == 0 {
        return 0, errors.New("division by zero")
    }
    return a / b, nil
}

Click a piece of the function above for a detailed explanation

Detail: Parameters

Go groups consecutive parameters of the same type: func divide(a, b int) means both a and b are int. Parameters are passed by value unless you explicitly pass a pointer.

Back to functions

Detail: The function body

Go functions are simple top-to-bottom blocks. There are no exceptions and no try/catch for ordinary failures. Errors are returned as ordinary values, which is why divide checks b == 0 explicitly and returns early.

Back to functions

Detail: The result value

When there is no error, this holds the computed result. By convention it is the first return value, with the error last. Always check the error before using this value.

Back to functions

Detail: The error value

error is a built-in interface. nil means no error occurred. This is Go's core error-handling idiom.

Back to functions

6. Structs & Methods

Go has no classes. Instead, a struct groups related fields, and you attach behavior to it with methods, which are functions with a special receiver argument.

type Server struct {
    Host string
    Port int
}

func (s Server) Address() string {
    return fmt.Sprintf("%s:%d", s.Host, s.Port)
}

Click the struct or the method for a detailed explanation

Detail: Structs

A struct is a typed collection of fields. Go has no inheritance; instead, Go favors composition, embedding one struct inside another to reuse fields and methods.

type Instance struct {
    Server
    Region string
}

Back to structs & methods

Detail: Methods and receivers

The (s Server) part is the receiver. Two flavors matter:

  • Value receiver (s Server) gets a copy and cannot modify the original.
  • Pointer receiver (s *Server) gets a reference, can modify the original, and avoids copying large structs.

Rule of thumb: use a pointer receiver if the method needs to modify the struct, or if the struct is large. Otherwise a value receiver is fine.

Back to structs & methods

7. Goroutines & Channels

This is Go's headline feature: lightweight concurrency built into the language, not bolted on as a library.

func worker(jobs <-chan int, results chan<- int) {
    for j := range jobs {
        results <- j * 2
    }
}

func main() {
    jobs := make(chan int, 5)
    results := make(chan int, 5)
    go worker(jobs, results)
    jobs <- 3
    close(jobs)
    fmt.Println(<-results)
}

Click a piece above for a detailed explanation

Detail: Goroutines

A goroutine is a lightweight thread managed by the Go runtime, not the OS. You can spin up thousands of them cheaply. Prefixing any function call with go runs it concurrently:

go worker(jobs, results)

main() itself runs in the first goroutine. If main() returns, the whole program exits immediately, even if other goroutines are still running. This is a common beginner bug, fixed with a sync.WaitGroup or by reading from a channel.

Back to goroutines & channels

Detail: Channels

A channel is a typed pipe for passing values between goroutines safely, with no manual locks needed. Go's philosophy is: do not communicate by sharing memory; share memory by communicating.

ch := make(chan int)      // unbuffered
ch := make(chan int, 5)    // buffered
ch <- 42                   // send
value := <-ch              // receive
close(ch)                  // signal no more values

Ranging over a channel, such as for j := range jobs, automatically stops once the channel is closed and drained. That is how the worker in the example knows when to exit.

Back to goroutines & channels

8. Error Handling

Go has no exceptions for ordinary error handling. Errors are just values, checked explicitly after every call that can fail:

result, err := divide(10, 0)
if err != nil {
    log.Fatal(err)
}
fmt.Println(result)

This looks repetitive coming from languages with try/catch, but it is deliberate: every place an error can occur is visible in the code. The one exception mechanism Go does have, panic/recover, is reserved for truly unrecoverable situations, not routine failures like a missing file or a failed network call.

9. Suggested Exercises

  1. Write a function that takes a slice of ints and returns the sum and the average, using multiple return values.
  2. Define a struct for a simple domain record, such as Domain with Name and Registrar fields, and give it a method that formats it as a string.
  3. Spawn three goroutines that each send a message to a shared channel, and print all three messages as they arrive in main().
  4. Rewrite a function that currently panics on a missing map key so it instead returns an error.
  5. Use embedding to compose two structs, and call a method from the embedded struct directly on the outer struct.
