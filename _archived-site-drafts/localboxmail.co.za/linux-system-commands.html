Handy Linux System Commands

A task-oriented command reference for inspecting files, disks, processes, networks, services and logs.

1. Command-line mental model

A command normally has a program name, options and arguments. Its output can be displayed, redirected to a file or passed to another command.

command --option argument
command > output.txt
command | another-command

2. Files and directories

CommandPurpose
pwdPrint current directory
ls -lahList including hidden files, permissions and sizes
cp -a source destinationCopy while preserving attributes
mv old newMove or rename
find /path -name '*.log'Find matching files
Be careful: rm removes immediately. Verify the path before using recursive deletion.

3. Storage

lsblk -f
df -h
du -sh /var/* 2>/dev/null
mount
findmnt

df answers "how full is the filesystem?" while du answers "which files or directories account for the usage?"

4. Processes

ps aux
top
pgrep nginx
kill PID
kill -TERM PID
kill -KILL PID

Use the normal termination signal first. A forced kill prevents the process from cleaning up files, sockets and transactions.

5. Memory and load

free -h
uptime
cat /proc/meminfo
vmstat 1

Linux deliberately uses free memory for cache. Available memory is usually more useful than the raw free number.

6. Networking

ip addr
ip route
ping -c 4 1.1.1.1
dig localboxmail.co.za
ss -tulpn
curl -I https://localboxmail.co.za
nc -vz host.example 443

These commands test different layers: interface addressing, routing, reachability, DNS, listening sockets, HTTP and raw TCP connection.

7. Services

Debian/Ubuntu systemd

systemctl status nginx
systemctl restart nginx
systemctl enable nginx

Alpine OpenRC

rc-service nginx status
rc-service nginx restart
rc-update add nginx default

8. Logs

# systemd
journalctl -u nginx --since today
journalctl -f

# ordinary log files
tail -n 100 /var/log/messages
tail -f /var/log/nginx/error.log
grep -i error /var/log/messages

Read logs before restarting repeatedly. The log usually contains the first concrete evidence of what failed.

9. Pipes and filters

ps aux | grep nginx
ss -tulpn | grep ':443'
du -sh /var/* 2>/dev/null | sort -h
grep -R "listen" /etc/nginx | less

Each command should do one small job. Pipes combine those jobs into a readable investigation.

10. Suggested exercises

  1. Find the five largest top-level directories under /var.
  2. Identify which process is listening on port 80.
  3. Prove whether a failed website test is caused by DNS, routing, TCP or HTTP.
  4. Compare service and log commands on Alpine and Ubuntu.
  5. Create a pipeline that displays only errors from the last 100 log lines.
