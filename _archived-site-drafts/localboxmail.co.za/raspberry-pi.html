1. Why Raspberry Pi?

A Raspberry Pi is a complete Linux computer on a board roughly the size of a bank card. It can run the same kinds of network services as a desktop or cloud server, while using little power and taking up very little space.

For LocalBox, the important advantage is not simply that the Pi is small. It exposes the whole system: power, storage, networking, operating system, services and physical sensors can all be studied together.

Low power

It can run from a 5 V supply, batteries, a compact UPS or a solar-backed system.

Real Linux

Users, permissions, packages, services, logs and networking behave like larger Linux servers.

Physical computing

GPIO, I2C, SPI and UART connect software to sensors and electronic devices.

3. Power and reliability

The Pi is powered from low-voltage DC. This makes backup power easier than it is for a conventional desktop. A good design includes a correctly rated supply, short power leads, protection against sudden shutdowns and a clear method to turn each board off safely.

Practical rule: low voltage does not mean power quality is unimportant. Undervoltage can cause unstable USB devices, SD-card corruption and unexplained crashes.

Small UPS arrangement

Battery pack -> charge/UPS board -> 5 V power bus -> individual switch -> Raspberry Pi

5. Networking

Ethernet is usually the most predictable connection for a server. Wi-Fi is useful where cabling is difficult. Bluetooth is well suited to nearby devices and sensors.

ip addr
ip route
ping -c 4 1.1.1.1
ping -c 4 localboxmail.co.za
ss -tulpn

The first ping tests basic IP reachability. The second also depends on DNS, so comparing them helps separate a network problem from a name-resolution problem.

6. GPIO and hardware interfaces

The GPIO header exposes digital pins and dedicated buses. These are not ordinary power-tolerant sockets: the GPIO logic is 3.3 V, and careless wiring can damage the board.

I2C

Two shared signal wires connect addressed sensors, displays and converters.

SPI

A faster clocked bus often used by displays, converters and storage devices.

UART

Simple serial communication using transmit and receive lines.

Safety: never feed 5 V directly into a 3.3 V GPIO input.

7. First boot checklist

  1. Write Raspberry Pi OS or Alpine Linux to suitable storage.
  2. Set the hostname and create a non-default user.
  3. Enable SSH only when needed.
  4. Connect Ethernet and boot the Pi.
  5. Find its address from the router, local DNS or console.
  6. Update packages and set the correct timezone.
ssh user@raspberrypi.local

8. Build a first web server

A useful first project is a static web server. It combines package management, service control, networking, files and logs.

# Debian / Raspberry Pi OS
sudo apt update
sudo apt install nginx
sudo systemctl enable --now nginx

# Test locally
curl -I http://127.0.0.1

Then open the Pi's IP address from another device on the same network. If it fails, check the service, listening port, firewall and route in that order.

9. Suggested exercises

  1. Identify every connector on your Pi and link it to a possible LocalBox service.
  2. Compare ip addr, ip route and ss -tulpn before and after starting a web server.
  3. Attach USB storage, mount it, and record the output of lsblk and df -h.
  4. Design a safe five-Pi power bus with one switch per Pi and room for airflow.
  5. Explain why a small rural clinic might prefer a low-power local server with delayed cloud synchronization.
